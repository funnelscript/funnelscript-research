# Phase 007C — Causal Event-to-Transaction Provenance v0

Status: PROPOSED opt-in reference integration, 2026-11-01. No accepted compiler, World or financial-automation ADR.

## Research anchors and falsifiers

Banks et al., *Discrete-Event System Simulation* (5th ed.), event calendar reproducibility and event vs post-state distinction; Law, *Simulation Modeling and Analysis* (5th ed.), verification is not empirical validation; Fowler, *Patterns of Enterprise Application Architecture* (2002), identity and unit-of-work boundaries; prior `spec/event-kernel-v0.md`, `spec/population-identity-rng-v0.md`, and `spec/financial-ledger-metrics-v0.md`. DEC-009 forbids model-owned financial assumptions in the compiler.

- **H-PROV1** (origin evidence): A financially relevant `Visitor.Tick` sale exists only when one actually processed event, in one named agent-local World run, matches an explicit source-state-to-target-state transition under an author-declared domain sale policy. An immutable witness records trial, agent, owner, name, event time, locally observed processed occurrence index, policy attribution, operation and transaction ID. Falsifier: a matching event with a false guard or missing matching transition posts revenue.
- **H-PROV2** (deterministic identity): Derive a versioned transaction identity from canonical structured data (trial, agent, local processed occurrence index, event fields, policy attribution and operation), independent of Python hash, agent iteration position, global draws and wall time. Falsifier: same inputs produce distinct trace IDs; different trial/agent/occurrence yields an alias. A processed-index witness is **not** the private heap insertion ordinal and is not stable if an agent's own earlier event history changes.
- **H-PROV3** (exactly once at integration boundary): Explicit idempotent retries with identical identity and value resolve to one posting; identity reuse with conflicting content rejects. An event without a matching actual step, a foreign trial, or unknown agent is rejected. No global event broker; all evidence is scoped to the supplied completed trial. Falsifier: re-delivery increases recognized revenue or mismatched witness is accepted.
- **H-PROV4** (temporal/accounting consistency): Event times are finite nonnegative integral simulation days for this opt-in policy; a qualifying transition recognizes a sale on its event day; ledger financial posting is ordered by `(day, kind-priority, stable transaction ID)` where costs precede sales and settlements follow sales. Explicit future settlements reference originating sale IDs, with minimum delay and balance enforcement delegated to the existing domain ledger. A cutoff snapshot never includes later postings. Falsifier: an uncollected sale increases cash or a future settlement alters the earlier snapshot.
- **H-PROV5** (noninterference): Tracing is opt-in on World/Population execution and must observe, not schedule, replay, or mutate World transitions. Default RNG, event calendar, compiler and legacy simulation remain untouched. Falsifier: trace toggle changes processed events, final states, emissions or stochastic samples.

## Choice, scope and governance

Option A (post hoc `RunResult.processed` only) is insufficient: it has no evidence that a guarded rule actually fired. **Select B**, a narrow read-only per-step World trace assembled inside the existing EventMachine reducer call and only opted into by PopulationExecutor. This is an adapter-local processed index, not a newly exposed kernel ordinal. Rejected C (new generic accounting scheduler/event-sourcing layer) for unjustified scope. Existing Phase 007B `MarketingLedger` is the sole money fold. Domain policy author explicitly selects exact event name, source/target field values, amount, currency and attribution. Terminal state alone never implies a sale. No new Accepted ADR; any shared mutable financial interactions or default World integration require separate review.

The reference financial adapter binds deterministic recognized sales to verified World steps; ad spend, costs, settlement and writeoff remain explicit externally-authored journal entries, distinguished from event-derived sales. These manual postings are not represented as source-caused World transitions. Events cannot be backdated by the adapter; settlement source IDs must resolve to a sale in the same trial. Every posted event-derived sale has exactly one witness in its returned trace. Duplicate processed events which do not actually perform a specified source-to-target transition must not create another sale.

Conservation for processed journal prefix: `cash = cash_initial + settlements - ad_spend - other_costs`; `receivables = recognized_sales - settlements - writeoffs`; `profit = recognized_sales - ad_spend - other_costs - writeoffs`. Partition identity union equals initialized IDs and partitions remain exclusive. Time is simulated **days**, not wall-clock time. The kernel never automatically schedules settlements. Incomplete runs (pending events beyond cutoff) can produce a prefix snapshot but never claim a completed causal horizon unless its provenance is scoped to that prefix.

## External validity

This verifies **model-declared transition consequences** and execution provenance, not experimental treatment effects, counterfactual marketing impact, causal inference on real audiences, credit risk calibration or forecast accuracy. Enrollment permutation results apply only under independent agent calendars and independent keyed RNG, not shared financial or social feedback loops.
