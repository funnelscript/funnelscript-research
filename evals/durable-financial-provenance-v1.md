# Phase 007E — Executed independent evidence

Reference scenario is hand-calculated in `spec/durable-financial-provenance-v1.md`. The experimental observations are preserved as raw JSON in `evals/durable-financial-provenance-measurements.json` (do not overwrite the Phase 007D receipt). Test the receipt with `uv run pytest -q tests/test_durable_financial_reference.py`; application tests live in `tests/test_durable_financial_audit.py` of `funnelscript`.

Distinct Python subprocesses re-execute an actual World population, restore the audit from a single-writer checkpoint with an out-of-band hash anchor, replay every previously persisted action and compare canonical bytes/ledger snapshots. Two seeds each for cohorts 10, 100, and 1,000; conversion count is 30% by declared event fixture, not calibrated field conversion data. Timings distinguish parent population/integration/serialization and child restore/replay. Parent traced memory excludes subprocess allocations. Process startup and publishing overhead is reported separately. Do not compare against Phase 007D as a performance regression proof without matched conditions.

Failure assumptions: honest original World execution witness, single writer, supported local filesystem atomic replacement, non-compromised independent anchor when supplied, complete checkpoint before acknowledgement. Altered records with recomputed hashes cannot be called authenticated. Shared budget/concurrent writes/physical delivery exactly-once and external authorization are explicitly unproven.

Final schema/versioned ownership experiment receipt (2026-11-01): six trials run in fresh child processes; 10-agent runs 9 entries and 3 sales; 100-agent runs 63 entries and 30 sales; 1,000-agent runs 603 entries and 300 sales. All six persisted digests match child-process re-export and all 6 replays preserve cash. The child restore durations ranged from approximately 0.001 s to 0.040 s under this workstation's environment; figures are raw individual measurements, not benchmarks or extrapolation. Exact observations and source/environment fingerprints are in the adjacent JSON.
